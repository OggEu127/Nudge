# 安全模型

## 信任边界

归档文件名、ZIP 内容、整合包 JSON、URL、HTTP 响应、缓存和已有目标文件均视为不可信输入。实例由启动器管理，安装路径只能落在选定的数据根目录内。

校验和证明的是“字节符合预期”，不是“内容无恶意”。Minecraft Mod、加载器、原生库和用户选择的 Java 本身能够执行代码。Nudge 不提供游戏进程沙箱，不保证不可信 Mod 安全；只导入可信作者和来源的内容。

## 路径与归档

- 拒绝绝对路径、`..`、反斜杠歧义、盘符、控制字符、Windows 设备名、尾随空格/点以及不安全分隔形式。
- 检查文件及父目录的符号链接和 Windows 重解析点；拒绝 ZIP 中的符号链接、特殊文件、文件/目录冲突，以及 Overrides 的大小写别名。加密条目在 ZIP 库要求密码时读取失败，安装随之中止；非 Overrides 条目只做精确重名检查，且不会被解压。
- 在 ZIP 库解析前检查目录记录与元数据预算，避免仅在展开后限制压缩炸弹。
- 为客户端正确选择 `overrides/` 与 `client-overrides/`，忽略服务端覆盖层；先暂存、验证，再提交。
- 导入不会自动运行归档中的安装脚本、程序或命令，也不会对用户提供的字符串进行 shell 求值。

默认 MRPACK 限额：

| 资源 | 上限 |
| --- | --- |
| 压缩包大小 | 2 GiB |
| 声明的总解压大小 | 4 GiB |
| 单个 ZIP 条目 | 512 MiB |
| ZIP 条目数 | 20,000 |
| 根清单 JSON | 8 MiB |
| ZIP 中央目录 | 32 MiB |
| 文件名元数据 | 4,096 字节 |
| 清单名称/版本 ID | 512 字节 |
| 单个文件的下载来源数 | 1–9 |
| 清单下载项 | 50,000 |
| 单个清单下载文件 | 2 GiB |

原生库提取另有更低限额，使用独立暂存目录。当前拒绝分卷 ZIP 和带 ZIP64 标记的中央目录结束记录；未超过大小限额、仅带 ZIP64 条目扩展字段的归档可能被正常处理。合法但超过支持边界的整合包会报错，不会放松防护后继续。

## 网络与 SSRF

生产传输只允许公网 HTTPS、443 端口，无 URL 用户名/密码和片段。主机名与 DNS 解析结果都检查；回环、私网、链路本地、保留地址及危险 IPv6 过渡形式被拒绝。含混合公网/内网结果的 DNS 响应也被拒绝，连接使用已验证的解析结果，避免重新解析造成 DNS rebinding。

MRPACK 的初始来源限定于 `cdn.modrinth.com`、`github.com`、`raw.githubusercontent.com`、`gitlab.com`。下载最多跟随 9 次重定向（含初始请求共 10 次网络请求），每次重新验证 URL 与目标地址；转向其他公网 CDN 不等同于允许转向内网。

生产传输明确禁用环境/系统代理，因为远程代理解析 DNS 会绕过本地已验证地址的连接保证。当前不支持必须经过代理的下载环境；不要为“修复网络”关闭 TLS 或公网地址检查。未来代理支持需要单独的可信代理威胁模型。

`NetworkPolicy::LoopbackOnly` 仅供测试通过显式依赖注入使用，生产入口不会选择该策略；它不能访问公网，也不能经重定向离开回环。该类型是公开 API，代码审查需确保生产调用方不启用它。导入文件不能切换网络策略。

携带令牌的认证请求使用单独的有界传输，不跟随任何重定向，不把请求/响应正文或 Authorization 放入诊断日志。

## 完整性、恢复与并发

已有文件与缓存必须通过长度和已声明全部摘要校验后才能复用。MRPACK 的 SHA-1 与 SHA-512 均为必需；官方游戏依赖按上游提供的 SHA-1 校验，不声称将上游未提供的强摘要凭空变为可信依据。

下载进入临时/partial 文件，通过验证才原子替换目标。正文持续有进展时不受固定总时长限制，连接与停滞检测仍有超时；元数据保持独立总超时。失败不会以半个文件覆盖此前完整目标。Range 续传仅在资源验证标识与服务器响应一致时使用，最终摘要仍不可省略。

下载引擎和实例操作有进程间文件锁。SQLite 保留任务状态；退出/取消后保留未完成记录与可恢复数据。不自动删除存档、用户 Mod 或失败现场，也不把未完成实例标记为可启动。

## 账号与日志

刷新令牌只进入操作系统凭据库；访问令牌只用于当前会话。公开账号元数据与配置不含令牌。无法使用或解锁系统凭据库时应报错，不回退到明文文件。

正常启动需取得明确选择的身份：微软账户经过 Java 版权限及档案检查；离线账户是单独标注的本地身份，不执行微软认证、不代表游戏所有权，也没有可用令牌。官方 demo 模式必须显式选择；不以离线身份或随机 UUID 冒充正版，不硬编码 token，也不借用其他启动器应用 ID。

游戏和 Mod 自身可能在 stdout、崩溃报告或参数中泄漏敏感信息。虽然 Nudge 的身份/参数 Debug 表示已脱敏，向第三方上传任何日志前仍需人工检查。操作系统同用户进程仍可能读取游戏进程内存或参数，这不是启动器能完全防御的边界。

## 已知限制与报告

静态路径/祖先检查不能宣称完全消除有本地写权限攻击者在检查与文件操作间制造的 TOCTOU 竞态。数据目录应由当前用户私有控制，不放在共享可写目录、恶意用户控制目录或可随意改写的网络挂载中。

进程监督会终止并回收直接启动的 Java 子进程，保留实例租约直到回收完成；不宣称隔离或终止 Mod 自行创建的整个后代进程树。继承输出管道的后代不会让启动器无限等待，但仍可能继续运行。

尚未提供自动安全更新、代码签名、独立渗透测试或 Windows 全面兼容认证。发行前应执行[发布清单](release.md)，并持续审查上游服务变化和依赖公告。

仓库当前没有 `SECURITY.md` 或公开安全联络方式；托管平台的私密漏洞报告是否已启用不能仅由代码树判断。发现漏洞时，若平台已提供 GitHub 私密报告入口，请优先使用；无论渠道状态如何，都不要在公开 issue 附上真实令牌、账号信息或可直接攻击的细节。维护者必须在正式发布前启用并记录一个可用的私密报告渠道。

持久化提交在重命名前后复查祖先链接和 Windows 重解析点。故障注入覆盖文件同步前、重命名前、提交后路径复查前的失败；只能证明这些注入点的可观察行为，不是实机掉电试验。Windows 安全 API 没有目录 fsync 的等价保证；持有本地写权限者仍可争抢剩余路径窗口，后续收紧应采用目录句柄相对操作并在 Windows 验证。
