# 下载记录与实例生命周期

## 当前实现

下载目的地的摘要预留用于阻止不同安装计划静默覆盖同一路径。普通 `run`、取消、失败和 `resume_pending` 都不会自动释放它。`DownloadManager::release_destinations(previous)` 是新增的显式底层接口：调用者必须持有实例锁，传入需要退役的旧任务及可信摘要。

- 释放与运行/恢复共用同一个跨进程引擎锁，忙时失败，不等待活跃下载完成。
- 在一个 SQLite 事务中核对所有目的地与相关任务的旧摘要，再删除任务及目的地预留；任何不匹配或损坏记录均回滚。
- 使用完整目的地匹配，包括 Windows 大小写规则；不使用字符串前缀或 `LIKE`，不接受空路径、父目录跳转和内部状态目录。
- 同一路径的旧任务会一起退役，防止 `resume_pending` 复活。恢复在取得引擎锁后才读取任务快照。
- 重复释放成功返回 0；新内容已经占位时，拿旧计划释放会失败。
- 不删除游戏文件、缓存或 partial。已下载的用户文件不会因释放记录丢失；无任务引用的 partial 暂时保留，后续单独设计 GC。

这个接口尚未接入实例删除、重装或升级命令；这些用户操作目前没有实现。它不负责推断所有权，也不会因为名称看起来属于某个实例就释放共享依赖。

## 删除与重装的协调协议

实现未来的上层操作时遵循以下顺序，统一锁顺序为实例锁 → 引擎锁；不允许持有引擎锁再等待实例锁。多实例操作按实例 ID 排序取得锁。游戏运行也持有实例锁，因此运行中拒绝操作。

1. 读取并验证已保存的旧计划；没有可信旧计划时拒绝自动释放。下载任务表不能单独充当实例拥有文件的证明。
2. 向实例外的操作目录持久化意图日志，包括操作 ID、实例 ID、旧/新计划摘要、精确退役目的地、操作阶段和是否保留存档。日志写入遵循文件刷盘、Windows 原子替换和路径复查。
3. 在实例锁内，把旧实例移入隔离回收目录或准备独立 staging。默认保留存档、截图、用户配置与未受管理文件；删除用户数据必须另有明确用户选择。禁止按整个数据根递归清除。
4. 调用 `release_destinations`，仅处理实例私有目的地。失败时保持意图日志和旧内容，允许再次启动后恢复。
5. 删除操作提交墓碑；重装操作用新计划在 staging 安装、校验后提交，再更新实例记录。上层恢复器在处理完未完成意图前，禁止普通下载恢复和启动该实例。
6. 提交完成后再清理隔离目录与操作日志；每个清理步骤可重复，崩溃后根据阶段继续。提交后的路径复查失败意味着结果不确定，必须重新读取磁盘状态，不能直接声称回滚或成功。

SQLite 与文件系统之间没有共同事务。意图日志及恢复门禁是必要部分，不能仅调用释放接口然后递归删除目录。释放成功、文件删除前崩溃时，恢复器必须先完成该意图，不能让普通安装抢占路径。

## 共享依赖与未来升级

`assets/`、`libraries/`、版本元数据和内容缓存可能被多个实例引用。当前没有可信所有者索引，因此删除/重装只能释放明确归属于该实例的私有路径。共享文件和预留保持不动。

升级功能应先增加版本化所有者表（实例/安装代次 → 目的地/摘要）及旧数据迁移规则。旧数据不能凭任务 ID 猜测所有者；应从经过验证的实例计划重建，无法确认的保留。共享引用降为零且没有活跃操作日志后，才允许单独回收。不同摘要争用同一共享路径仍然拒绝，不靠释放记录强行覆盖。

升级使用新安装代次和完整新计划，不能原地逐个覆盖唯一一份旧文件。先准备和校验新内容、计算用户修改与受管理文件的差异，再原子切换代次。修改过的 Mod/配置需要保留或报告冲突；失败保留旧代次可启动及可恢复的新 staging。

## 验证

自动测试覆盖：摘要不匹配时整批回滚、引擎互斥、重复释放、保留其他目的地、保留用户文件、清空后恢复不发请求、新摘要重新占位。上层操作尚未实现，未来必须增加各持久化阶段的进程中断、恢复与共享引用测试，不能把底层接口测试等同于删除/升级验收。
